    One-time redemption posture

    Activation keys are generated with an OS CSPRNG and stored only as keyed HMAC-SHA256 digests. Redemption locks the key row, binds one device identifier and issues a separate high-entropy credential. The original activation key is never returned again.

    SINGLE ISSUANCE

    Generate key

    Create one one-time activation key for a reader device.

    Key format NEXORA-XXXX-XXXX-XXXX-XXXX 80 bits of CSPRNG entropy · plaintext shown once

    What happens next

    The activation key is a bearer secret until redeemed.

    1. 01
      Copy once

      The plaintext key appears only in the creation dialog. The database stores a masked hint and an HMAC digest.

    2. 02
      Reader redeems

      The reader calls POST /api/reader/redeem with the key and its device id. The key row is locked during the transition.

    3. 03
      Credential issued

      The response contains a one-time device credential. Only its keyed digest is stored, and the original activation key is never returned.

    4. 04
      Admin controls trust

      Revoke a reader at any time. Its credential is cleared immediately and further authentication fails.

    BATCH ISSUANCE

    Bulk generate

    Issue a unique batch in a single database transaction.

    Batch policy UNIQUE · ONCE · HMAC-SHA256 Duplicate hashes are prevented by a unique database index.

    Batch safety

    Plaintext batch material exists only in the response.

    • ✓
      Single transaction

      Every key in the batch is inserted under one transaction and one audit entry.

    • ✓
      Unique by construction

      A collision retries with fresh CSPRNG output; the unique index is the final guard.

    • ✓
      Copy or download

      Copy individual keys, copy all, or download a one-time text file from the result dialog.

    • ✓
      No retrieval later

      The API and database never expose a stored plaintext key. Masked hints remain for operations.
